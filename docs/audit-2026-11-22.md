## Findings (most severe first)

1. **Fixed: a battle's stake was lost when the page was reloaded or closed** (browser-only mode). Reproduce: create a battle, reload in the lobby or during the rounds. Expected: refund in the lobby, payout of the decided result once started (what leaving through a link already did). Actual: the stake was gone and the battle vanished. Fix: `src/views/battles.ts` runs the same settle-or-refund step on `pagehide`. Re-run: the lobby refund came back (48.92 to 48.59 to 48.92), and a battle reloaded mid-round paid 0.62 on 0.85 and reconciled.
2. **Fixed: selling an item counted as winnings and left no transaction** (browser-only mode). The server wallet records an "Item sale" that is not a win. Fix: `src/views/inventory.ts` uses `grant(value, 'Item sale')`.
3. **Fixed: focus was lost after closing the account window** opened from the account menu (it went to the page body). Fix: `src/app.ts` focuses the menu button before opening the window.
4. **Fixed (hardening): a damaged save could break every game.** A list field holding a string made the first bet throw. Fix: `src/state.ts` drops list fields that are not lists and a balance that is not a number.
5. **Fixed (test): `tests/catalogue.test.ts` timed out (5.1 s) under the full parallel run** but passes alone in 0.65 s. The timeout is now 30 s.
6. **Open, low:** a guest's blank default state is written to storage once at start-up (before sign-in is known). Nothing personal; it contradicts "signed-out state is never saved". Decide if worth changing.
7. **Open, cosmetic:** in the account window on a phone the close button sits over the sideways-scrolling tab strip. The strip keeps 52 px of padding so every tab stays reachable.
8. **Open, by design:** an unreadable save resets that browser account to a fresh 100 coins, including its display name.

## Trust boundary

- **Cloud mode (the live site):** balance, items, prices, case odds, game outcomes and limits are decided and stored by the database (security-definer functions, row-level security; clients cannot write any money table or call the helper functions). The page only displays them; editing the page or its storage changes nothing on the server. Admin actions are checked on every call (staff role, two-factor session, unlocked admin session, permission) and audited.
- **Browser-only mode (no backend configured):** everything is in `localStorage` and can be edited by the player. This is documented as a demo fallback and is not what the live site runs.
- No credentials or secret values were logged or written to this report.

## Ten common attacks (2026-11-25)

The owner shared a list of ten attacks and their usual fixes. How Vaultrush stands against each (no code change was needed):

| Attack | Usual fix | Vaultrush |
|---|---|---|
| SQL injection | Parameterized queries | Every query is parameterized; table and column names only through `format('%I')` from fixed lists. The owner's Data explorer runs free SQL by design: read-only, logged, owner only |
| XSS | Escape output + CSP | All player text is escaped; strict CSP with no inline scripts (since 2026-11-25) |
| CSRF | CSRF tokens, SameSite cookies | Not applicable: the session is sent as a bearer token in a request header, not as a cookie, so another site cannot make the browser send it |
| DDoS | Rate limits, CDN / WAF | Vercel's CDN serves the page; Supabase sits behind Cloudflare; database rate limits on chat and promo codes; caps on open games |
| Man in the middle | HTTPS everywhere | HTTPS only, with HSTS preload on the site; Supabase is HTTPS and WSS only |
| Brute force | Lockouts, rate limits, MFA | Admin password locks for 15 minutes after 5 tries and needs an authenticator; promo codes 10 wrong tries per 10 minutes; Supabase Auth limits sign-in attempts; players can turn on two-factor, and the site then asks for the code after every sign-in method (Google, Steam, e-mail) |
| Phishing | Check the URL + MFA | Sign-in goes only through Google, Steam or Supabase pages; Steam returns only to allow-listed addresses; MFA available for players, required for admins |
| Session hijacking | HttpOnly, Secure, rotated cookies | Supabase keeps the session in the browser's storage (readable by scripts), so the defence is the CSP and escaping above; access tokens last 1 hour, compromised refresh tokens are detected and revoked, and a refresh token can be reused for only 10 seconds (Supabase dashboard, Authentication, Sessions; confirmed by the owner 2026-11-25; session time limits need the Pro plan); the Steam sign-in token is removed from the address at once and works only once |
| Path traversal | Normalize paths + allowlist | No server code reads files from a requested path; the site is static files on Vercel |
| Clickjacking | frame-ancestors 'none' | Both sites send `frame-ancestors 'none'` and `X-Frame-Options: DENY` |
